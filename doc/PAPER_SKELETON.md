# 论文骨架：单入口控制器模型下的双向同周期数据流不可满足性

## 0. 一句话定位

> 在 `ros2_control` 的**单入口控制器模型**（每个控制器每周期恰好一次 `update()`）下，
> 同一对父子控制器之间的**双向同周期数据流不可满足**：
> 「父本周读到子刚算出的状态」要求子先跑，「子本周用到父刚产生的参考」要求父先跑，两者矛盾。
> 上游的 state chaining 与 reference chaining **各自只覆盖单向场景**，
> 双向场景**未被覆盖**，且在单入口模型下**无法覆盖**。
> 本文用「**一个线性顺序 + 两个相反遍历方向**」的显式两阶段契约修复它，
> 证明其充分性与零额外存储，量化其代价，并给出上游不具备的可靠性契约。

**必须避免的旧叙事**（已放弃，见 `HANDOFF_MANUAL.md` §1.4）：
"给 `ros2_control` 引入层次化调度 / 接口依赖图"——**上游已做**，不成立。

### 第 3 章 形式化模型与不可能性（**论文核心**）

- 3.1 模型：`V`、参考边 `R`、状态边 `S`、阶段函数 `Update`/`Handle`、调度、滞后 `λ`

- 3.3 **推论 1**（参考一致的单趟 ⇒ 状态边必陈旧）

- 3.7 与上游的对应：上游同时用 `R` 与 `S` 求**一个**顺序 ⇒ 按定理 1 无解，

### 第 4 章 上游行为的实证

### 第 5 章 两阶段契约与实现

- 5.1 设计准则
  - 一个线性顺序，两个相反遍历方向（= FineMote 的 `Update()`/`Handle()`）
  - 状态阶段 `postorder` 正向（子先于父）；命令阶段**同一顺序反向**（父先于子）
  - **一个顺序就够**：不要维护两份拓扑数组
- 5.2 数据契约 `StagedFrame`（`cycle` / `sample_ns` / `valid` / `fault_code`）
  - 复合状态的 `sample_ns` 由执行组用**最旧子节点采样时间**覆盖 ⇒ 无法"重新盖章伪装新鲜"
- 5.3 失败语义
  - 状态阶段失败 ⇒ **不进入**命令阶段
  - 命令阶段失败 ⇒ **任何 sink 都不被调用** ⇒ 不产生"部分新、部分旧"
  - **保留上一周期命令不是安全策略**，应用必须自己定义故障动作
- 5.4 两种宿主
  - manager 宿主（`ControllerManager` 薄适配）
  - **库宿主**（`create_library`，不改 manager）
  - 二者复用**同一份内核**
- 5.5 实时路径约束（重要工程发现）
  - **实时路径禁止获取 `controllers_lock_`**：`switch_controller()` 持锁等待实时线程
    ⇒ 实时线程抢锁会**永久自旋**（死锁）
  - 正确做法：非实时线程可加锁；实时路径只用**脏标志**在下一周期开头重建

**证据入口**：`hierarchical_control/include/hierarchical_control/*.hpp`；
`controller_manager/test/test_staged_execution_group.cpp`（6 用例）；
`doc/STAGED_EXECUTION_GROUP_EXPERIMENT.md`；`hierarchical_control/README.md`。

### 第 6 章 代价量化：滞后值多少

- 6.1 **框架转换**：滞后 `L` = 纯传输延迟 `τ = L·Δt`
- 6.2 **相位裕度定律**：`ΔPM = ω_c·L·Δt`（`= 360·f_c·L·Δt` 度）
  - 关键：与 `f_c·Δt` 成正比 ⇒ 危害是**相对的**
- 6.3 **带宽上限**：`f_c ≤ B/(2π·L·Δt)`；`B=30°`、`Δt=1 ms` 时
  深度 2 → 42 Hz、深度 4 → 21 Hz
- 6.4 **调度侧闭环验证**（本轮新增，`SCHEDULING_PERFORMANCE_COST.md` §2）
  - 被控例 `x'' = u`，`kp=100`，控制器 1 kHz，**精确离散化**
  - 可用增益上限：`L=1,2,3` → **1570.8 / 785.3 / 523.5**；比值 **2.000 / 3.001**；`L=0` **无上限**
  - 相位裕度定律**预测**失稳起点，时间域**确认**（`τ₀·0.9` 有界、`τ₀·1.3` 发散）
  - 代价由**绝对延迟**决定：同样 1 周期，100 Hz 的损失是 1 kHz 的 **10.00 倍**
- 6.5 工程结论：**深度不只是"多跑几层"，它限制你能做多快的控制**
- 6.6 非线性稳健性：摩擦与量化**不改变**结论（<0.1%）；饱和**掩盖**失稳而非消除
  - ⚠ **但 6.6 的证据待复核**：其 `kd_max` 建立在显式 Euler 上，见 §7.4

**证据入口**：`doc/CONTROL_COST_OF_LAG.md`；
`hierarchical_control/test/test_stale_state_cost.cpp`;
`hierarchical_control/test/test_scheduling_performance.cpp`（4 用例）。

### 第 8 章 方法学：我们踩过的坑（**必须写**）

审稿人一定会问"为什么第一版看不出差别"，因此这一章是**必需**的：

1. **陷阱一：子状态必须不可被父廉价重推导**
   - 第一版叶状态是 `travel += ∫v·r dt`，父可以自己读 `wheel/position` 乘半径得到 ⇒
     **不构成依赖**，案例研究因此看起来"机制没用"
   - 修正：改用**滤波器内部状态**（`filtered_velocity_`，`α=0.85`），
     依赖控制器自身历史，父**无法**从瞬时关节位置重建
   - 推广：父能用输入与已知几何重算的量，**不构成依赖**
2. **陷阱二：评估指标必须对纯延迟敏感**
   - RMS 轨迹误差对 1–3 个周期**不敏感**（实测比值 0.97–1.00）
   - 敏感指标：相位裕度、可用增益上限、失稳点、阶跃初始滞后周期数
   - 本轮进一步精确化：**能用跟踪误差看到收益的场景，与滞后造成危害的场景不是同一个场景**
     （低带宽回路不敏感；带宽受限回路的小信号误差由参考主导）
3. **陷阱三：饱和会掩盖不稳定**
   - 「不炸了 ≠ 能工作」；带饱和的系统必须**同时报告跟踪误差**
4. **陷阱四（本轮新增）：数值积分格式会冒充控制结论**
   - 显式 Euler 的 `Δt·kd > 2` 上限被误读为"可用增益预算"，且因有效阻尼 = `kd`
     而**精确呈现 `1/(L+1)`**，看起来与理论"吻合"
   - 教训：**代价量化必须核查积分格式**，否则在报告控制极限时会报告求解器极限
5. **因果对齐用整数周期对齐**，不用浮点时间戳（时间戳抖动会污染结果）

## 5. 负结果章（单独成节，见 `doc/WHY_NO_SPEEDUP.md`）

1. **不更快**：约 2 倍中位耗时；结构性原因（多一次遍历 + 每控制器多一次虚调用 + 帧校验）；
   并说明测的是 **CPU 时间**，而 FineMote 主张的是**控制延迟**，两者不是同一个量
2. **跟踪误差无收益**：报告并给出两个原因（低带宽不敏感；能暴露效应的回路其 RMS 不敏感），
   作为**方法学贡献**而非缺陷
3. **省集成代码不独有**：库宿主同价 ⇒ 否定扩展 `ControllerManager` 的必要性
4. **一个被误读为收益证据的数值伪影**：`1 : 0.502 : 0.311 : 0.225` 是 `Δt·kd = 2` 上限；
   真实上限 1570.8 / 785.3 / 523.5（比值 2.000 / 3.001），`L=0` 无上限

## 6. Threats to Validity（取自 `FORMAL_MODEL.md` §8，已更新）

1. **模型假设**：`Update` 不依赖父本周期输出；若依赖则 `G` 含环，定理 3 不适用，
   且当前内核**尚不能表达**这种边
2. **"零滞后"是周期数意义**：不代表零物理延迟、总线原子性或 WCET 保证
3. **单频同步**：不含多频、异步回调、动态拓扑
4. **只讨论新鲜度**：不建模数值稳定性、饱和、积分饱和等控制性质
5. **实验规模**：内核穷举 3 节点（6 种顺序）；管理器/Gazebo 为 3 节点链与两轮差速
6. **移植证据强度**：Jazzy 结论为**逻辑移植 + 源码比对**，非运行上游代码
7. **代价一侧**：不更快、省集成代码不独有；这些负结果界定适用边界
8. **新增**：代价量化的时间域证据受**积分格式**影响；本文已改用精确离散化，
   但 `CONTROL_COST_OF_LAG.md` §8 的旧证据**待复核**
