## 0. 结论

**当前实现把"两端不在同一速率桶"的参考边一律拒绝（`cross_rate_dependency`）——这个规则比必要的更严。**

对父桶 `f_P`、子桶 `f_C`（单位：管理器周期；`g = gcd(f_P, f_C)`），两趟调度的**最坏滞后是精确可达的**，
不是松上界：

| 边方向 | `f_C > f_P` | `f_C == f_P` | `f_C < f_P` |
|---|---|---|---|
| **状态边**（子→父，`update_phase`） | `f_C` | `0` | `f_C − g` |
| **参考边**（父→子，`handle_phase`） | `f_P − g` | `0` | `f_P` |

（单位：管理器周期。`× T` 即时间；除以消费者自己的周期即"消费者周期数"。）

**两条直接可用的推论**：

1. **参考边同周期新鲜 ⟺ `f_P | f_C`**（含相等）。也就是说：**父比子快（或等）且周期调和时，
   参考方向本来就是零滞后**，现在却被拒绝。
2. **状态边同周期新鲜 ⟺ `f_C | f_P`**（含相等）。对称地：**子比父快（或等）且调和时，状态方向零滞后**。

两个方向**不能同时**零滞后，除非 `f_P == f_C`——这与"同一条线性化、两个相反方向"的直觉一致，
也解释了为什么当前实现只在同桶内承诺零滞后。

## 1. 模型与假设

模型精确复刻 `feature/two-phase-manager` 的 `ControllerManager::update()`：

```cpp
// 状态趟：桶按【升序】，桶内把控制器列表【反向】走 → 桶内子先于父；跨桶则小 factor 先跑
for (const auto factor : buckets) { if (update_loop_counter_ % factor) continue; /* 反向 */ }
// 命令趟：桶按【升序】，桶内把控制器列表【正向】走 → 桶内父先于子；跨桶仍是小 factor 先跑
for (const auto factor : buckets) { if (update_loop_counter_ % factor) continue; /* 正向 */ }
```

（`controller_manager/src/controller_manager.cpp` 两趟段落；列表是 parents-first。）

两条假设**由实现本身保证**，不是额外前提：

| 假设 | 由谁保证 |
|---|---|
| 该边的两端在列表里是父在子前 | 准入的 `unschedulable_order` 拒绝（否则边不成立） |
| factor 为 `f` 的成员，其到期集合**恰好**是 `f` 的倍数 | 准入要求 `update_rate_ % controller_rate == 0`，故 `factor = update_rate_ / controller_rate` **整除** `update_rate_`，计数器的取模回绕不会扰动到期集合 |

> 第二条值得单说：管理器的计数器是 `(counter + 1) % update_rate_`。如果 factor 不整除
> `update_rate_`，回绕会让到期集合出现"两次相邻到期"的畸变（例如 rate=100、factor=3 时
> 99 与 0 同时到期）。**准入规则恰好排除了这种情况**，所以模型与实现一致。这一点必须写进论文，
> 否则"周期分桶"的推导会被审稿人用回绕反例打掉。

## 2. 推导

设 `L` 为控制器列表（parents-first），`P` 为父（factor `f_P`）、`C` 为子（factor `f_C`）。

**状态趟**（`C` 发布、`P` 摄取）：

* 桶升序遍历，故当 `f_C < f_P` 时 `C` 的桶整桶先于 `P` 的桶；当 `f_C > f_P` 时反之；相等时在同一桶内，
  桶内**反向**走使得 `C` 先于 `P`。
* 于是 `P` 在**同一周期**看到 `C` 本次发布，当且仅当 `f_C ≤ f_P`。
* 当 `f_C > f_P` 时，`P` 永远先跑，因此在**共同到期**的周期上 `P` 读到的仍是 `C` 上一个周期的值，
  滞后 `f_C`；因为 `f_C | lcm`，该值可达。
* 当 `f_C < f_P` 时，`P` 在非共同到期的周期上读 `C` 的最近一次发布，最大偏移是
  "`P` 到期点在 `C` 到期格点之下能落到的最大距离"，在周期 `lcm(f_P, f_C)` 上等于 `f_C − g`；
  特别地 `f_C | f_P` 时为 0。

**参考趟**（`P` 写、`C` 读）：与上完全对称，但因为桶内方向是**正向**（父先于子），
"同一周期可见"的条件变成 `f_P ≤ f_C`，并且当 `f_P > f_C` 时 `C` 的桶整桶先跑，
连共同到期周期也要付 `P` 的**整个周期**，故为 `f_P`。

**可达性**：到期集合与访问顺序都以 `lcm(f_P, f_C)` 为周期，故上述最坏值在稳态中反复出现，
是**紧的确切值**而非上界。脚本对 `1 ≤ f_P, f_C ≤ 12` 的全部 144 组配置逐周期仿真，
与闭式**逐项相等**（不一致即退出码 1）。

## 4. 对 P0-2 的后果：准入应当怎么改

当前规则：**边两端桶必须相等**（`f_P == f_C`），否则拒绝。

按 §0 的结果，正确规则应当是**按方向检查**，并把"滞后预算"显式化：

| 配置 | 参考边（父→子） | 状态边（子→父） | 是否应当接纳 |
|---|---|---|---|
| `f_P == f_C` | 0 | 0 | 现在接纳 |
| `f_P | f_C`（父快/等，调和） | 0 | `f_C`（可声明） | 参考方向**无损**；状态方向按预算决定 |
| `f_C | f_P`（子快/等，调和） | `f_P`（可声明） | 0 | 状态方向**无损**；参考方向按预算决定 |
| 非调和 | `f_P − g` | `f_C − g` | 两个方向都要预算 |

也就是说，准入应从"**同桶**"放宽为"**声明一个以管理器周期为单位的滞后预算 `max_lag_cycles`，
逐边计算并比较**"，并且**把计算出的上界写进准入报告**（论文需要它）。
`f_P | f_C`（或反向）的**零滞后方向**应当**无条件接纳**——这是当前实现白丢的能力。

**注意一个反直觉点（值得写进论文）**：`f_P | f_C`（子更慢、周期调和）时，
**参考方向是零滞后而状态方向要付整个子周期**。这与 FineMote 的调和推论方向一致，
但本文给出的是**精确可达值**，而不是仅上界。
