# 形式化模型：单趟不可满足性与两趟充分性

日期：2026-09-21
关联：`doc/BIDIRECTIONAL_EDGE_ANALYSIS.md`（上游实证）、`doc/TWO_PASS_VS_SINGLE_PASS.md`（内核与管理器实现和实测）

本文给出课题的**形式化核心**：模型、三个定理、一个配置期校验推论，以及与实现和实验的对应。
定理的证明都很短，并且都有对应测试（`hierarchical_control/test/test_execution_group.cpp`）。

---

## 1. 模型

### 1.1 节点与量

控制器集合 `V = {1..n}`。每个节点 `i` 在周期 `k` 具有：

| 符号 | 含义 |
|---|---|
| `x_i(k)` | 周期 `k` 结束时的**内部状态**（估计、积分器、滤波器状态等） |
| `u_i(k)` | 周期 `k` 产生的**输出**（参考或执行器命令） |
| `h_i(k)` | 该周期可用的**硬件/外部输入** |

### 1.2 两条边

对父 `p` 与子 `c`：

- **参考边** `(p,c) ∈ R`：`u_p` 被 `c` 当作参考消费（父产生、子消费）；
- **状态边** `(c,p) ∈ S`：`x_c` 被 `p` 消费（子产生、父消费）。

两者可以**同时**存在于同一对 `(p,c)`：父需要子算出的估计，子需要父产生的参考。
这正是级联控制（PDS、POV 底盘）的常态。

### 1.3 阶段函数

```text
Update :  x_i(k) = f_i( x_i(k-1), { x_j(k) : (j,i) ∈ S }, h_i(k) )      // 摄取，改内部状态
Handle :  u_i(k) = g_i( x_i(k),   { u_p(k) : (p,i) ∈ R } )              // 由状态产生输出
```

两个约定：

1. `Handle` 用**本周期**的 `x_i(k)`，即同一节点的 `Update` 必须先于 `Handle`；
2. `f_i` 可以是任意函数（含历史依赖），本文只讨论**数据新鲜度**，不讨论数值稳定性。

### 1.4 调度与新鲜度

- **单趟调度**：一个全序 `π = (π_1..π_n)`；每周期按 `π` 顺序，每个节点执行一次**融合调用**
  （在同一次调用里算 `x_i(k)` 与 `u_i(k)`），只能读到此前已被本周期写入的值。
- **两趟调度**：一个全序 `L`；先用 `reverse(L)` 跑一遍 `Update`，再用 `L` 本身跑一遍 `Handle`。
- **滞后** `λ ≥ 0`：某条边上，消费者在本周期用的是生产者**本周期**的值时 `λ = 0`（**新鲜**）；
  用 `m` 个周期前的值时 `λ = m`。

## 2. 定理 1（单趟不可满足性）

> 若 `(p,c) ∈ R` 且 `(c,p) ∈ S`，则**任何单趟调度**都使这两条边中至少一条的滞后 `≥ 1`。

**证明.** 融合调用读取"此前本周期已写入"的值。

- 使状态边新鲜（`p` 的 Update 读到 `x_c(k)`）要求 `c` 的融合调用先于 `p`，即 `pos(c) < pos(p)`；
- 使参考边新鲜（`c` 的 Handle 读到 `u_p(k)`）要求 `p` 的融合调用先于 `c`，即 `pos(p) < pos(c)`。

两式矛盾，故至少一条滞后 `≥ 1`。∎

**测试**：`every_single_pass_order_is_stale_in_some_direction` 穷举 3 节点链的全部 6 种顺序，
断言**每一种**都至少有一个方向滞后 `> 0`。

---

## 3. 推论 1（参考一致的单趟 ⇒ 状态边必陈旧）

> 设 `π` **尊重参考边**（对所有 `(p,c) ∈ R` 有 `pos(p) < pos(c)`）。则同时具有两条边的每一对，
> 其**状态边滞后 `≥ 1`**。

**证明.** 若状态边滞后为 0，则 `pos(c) < pos(p)`，与 `pos(p) < pos(c)` 矛盾。∎

**意义**：任何"正确"的管理器顺序都必须尊重参考边（否则子节点拿到陈旧参考，控制上更糟）。
因此**单趟 + 尊重参考边 ⇒ 状态方向必然陈旧**，这不是实现缺陷，而是结构性结论。

---

## 4. 定理 2（深度正比滞后）

> 设 `n_0 … n_D` 是一条链，每级同时有参考边 `(n_i, n_{i+1}) ∈ R` 与状态边 `(n_{i+1}, n_i) ∈ S`。
> 若 `π` 尊重参考边，则叶节点 `n_D` 的信息到达根 `n_0` 的滞后**恰好为 `D`**。

**证明.**

- 下界：由推论 1，每级状态边滞后 `≥ 1`，故每级至少增加一个周期：
  `x_{n_i}(k)` 依赖 `x_{n_{i+1}}` 在周期 `≤ k-1` 的值，归纳得依赖 `h_{n_D}` 在周期 `≤ k-(D-i)` 的值。
  取 `i = 0` 得滞后 `≥ D`。
- 上界：取 `π = (n_0, …, n_D)`，归纳可得 `x_{n_i}(k) = F(x_{n_{i+1}}(k-1))`，故滞后 `≤ D`。

两者合起来给出 `= D`。∎

**测试**：`one_pass_can_keep_only_one_direction_same_cycle` 用阶跃响应测出
root 滞后 `2`、mid `1`、leaf `0`（`D = 2`），下行全 `0`。
**管理器级复现**：`test_two_phase_execution.cpp` 在真实 `ControllerManager` 上得到同样的 `0/1/2`。

**注**：若允许不尊重参考边的"混合顺序"，某些级的上行滞后可以小于 `D`，
但代价是参考方向变陈旧——总有一个方向受损。定理 1 仍然成立。

---

> **滞后的工程代价**见 `doc/CONTROL_COST_OF_LAG.md`：`L` 个周期的滞后是纯传输延迟 `L·Δt`，
> 使相位裕度损失 `ω_c·L·Δt`；`Δt = 1 ms`、95 Hz 穿越频率下，深度 2 吃掉 69°、深度 3 失稳。
> 这是定理 2 的"so what"。

## 5. 定理 3（两趟充分性）

设
```text
G = { (p,c) : (p,c) ∈ R }  ∪  { (p,c) : (c,p) ∈ S }        // 统一为"父先于子"方向
```
若 `G` 无环，则存在全序 `L` 使 `G` 的每条边都满足 `pos_L(p) < pos_L(c)`。

> 两趟调度（`reverse(L)` 跑 Update，`L` 跑 Handle）使**每条边的滞后都为 0**。

**证明.**

- **状态方向**：对 `(c,p) ∈ S`，由 `G` 的构造 `L` 中 `p` 在 `c` 之前，故 `reverse(L)` 中 `c` 在 `p` 之前，
  `p` 的 Update 读到 `x_c(k)`。滞后 0。
- **参考方向**：对 `(p,c) ∈ R`，`L` 中 `p` 在 `c` 之前，故 `c` 的 Handle 读到 `u_p(k)`。滞后 0。
- 整个 Update 趟先于整个 Handle 趟完成，故 `g_i` 总是看到本周期状态。

∎

**存储**：只有一个顺序 `L`，两个方向由正向/反向遍历得到——**与 FineMote 的线性注册表一致，`O(|V|)`**。

**测试**：`one_pass_can_keep_only_one_direction_same_cycle` 的后半段（两趟，两方向滞后均 0）；
`test_two_phase_execution` 的管理器级用例（全 `0`）。

**与实现对应**：内核里 `L = reverse(plan_.postorder)`，Update 走 `postorder` 正向，
Handle 走 `postorder` 反向。`build_controller_hierarchy` 在配置期拒绝环、多根、不可达节点，
即已保证 `G` 无环（在状态边与树方向一致的前提下）。

## 6. 推论 2（`G` 无环是**充分**条件，不是必要条件）

> **修正（2026-09-23，外部评审 R2）**：本节早期版本写的是"若 `G` 含环则任何调度都不可能"。
> **该命题是错的，已撤回。**
>
> 反例：设 reference 边 `A→B`，状态边也是 `A→B`。按本节的画法（状态边翻转）会得到 `G` 中的
> `A↔B`，看似成环；但实际约束是 `S_A → S_B`、`C_A → C_B`、`S_A → C_A`、`S_B → C_B`，
> 合法执行 `S_A, S_B, C_A, C_B` **可以**全部同周期满足。
>
> 正确的表述只有**充分性**方向：

> **推论 2（充分条件）.** 若 `G` 无**有向环**，则"一个线性顺序 + 正反两趟"的调度满足
> `G` 的全部同周期要求。反之**不成立**：`G` 有环只说明**该表示**不足以覆盖该拓扑，
> **不能**推出任何阶段调度都不可能。

**证明.** `G` 无环 ⇒ 存在拓扑序；把它作为 `L`，正向走一趟即可满足 `G` 的每条边。∎

**意义与边界**：`G` 的无环性仍可作为一条**配置期校验规则**（在进入实时循环前拒绝
"该表示覆盖不了"的拓扑），但**不能说它等价于"拓扑不可满足"**。
要判断一般阶段调度是否可能，必须在**实际阶段顶点**（第 i 趟的状态阶段 `S_i` 与命令阶段
`C_i`）构成的依赖图上查环，而不是在合并后的 `G` 上——这一步**尚未实现**（见第 8 节）。
当前 `Spec` 只能表达"状态边 = 树结构的反向"，故 `G` 就是树的定向，天然无环。

## 7. 与上游 ros2_control 的对应

上游是**单趟**（每个控制器一个 `update()`），并且**同时**用 `R` 与 `S` 求一个顺序：

- `build_controllers_topology_info()` 把 `R` 写成 `following/preceding`，把 `S` 也写成
  `following/preceding`（方向相反）；
- 排序启发式遇到双向对时，`if (already in ordered) return;` 让**先插入者胜**，
  于是**静默**退化为一周期延迟，且哪条边陈旧取决于控制器**加载顺序**。

**Humble 的机制不同但结论相同**：其 `controller_sorting` 比较器在参考边处**提前返回**，
状态边的子句（带 `TODO(saikishor): deal with the state interface chaining`）在双向对上
**不可达**，即状态边从未参与排序。因此 Humble 是**确定的** reference-first，
而 Jazzy/master 是**随加载顺序翻转**的。插桩实测见 `BIDIRECTIONAL_EDGE_ANALYSIS.md` §9。

按定理 1，这不是启发式写得不好，而是**单趟模型下无解**。上游的 state chaining 与
reference chaining 各自覆盖单向场景；**双向场景是未被覆盖的区域**。

**反例防护核验（2026-09-21）**：检索上游文档与 issue，**未发现**任何禁止
"同一控制器对同时具有 reference 与 state 边"的规定；
反而 [issue #2189](https://github.com/ros-controls/ros2_control/issues/2189) 说明
preceding/following 术语本身在文档中就不清楚（已关闭，属文档澄清）。
因此本文的表述应为"**该组合未被覆盖**"，而不是"上游禁止了它"。

## 8. 威胁与限制（写进论文的 Threats to Validity）

1. **模型假设**：`Update` 不依赖父节点本周期输出。若依赖，`G` 含环，定理 3 不适用；
   当前内核**尚不能表达**这种边，因此也还不能在配置期检出该环。
2. **"零滞后"是周期数意义**：不代表零物理延迟、总线原子性或 WCET 保证。
3. **单频同步**：模型不含多频、异步回调、动态拓扑；这些在实现中也未支持。
4. **只讨论新鲜度**：不建模数值稳定性、饱和、积分饱和等控制性质。
5. **实验规模**：内核级穷举 3 节点（6 种顺序）；管理器级 3 节点链。
   未在真实机器人动力学、真实硬件或 Gazebo 上验证。
6. **移植证据的强度**：`BIDIRECTIONAL_EDGE_ANALYSIS.md` 是**逻辑移植**而非运行上游代码；
   在 Jazzy/Rolling 上的真实复现仍待完成。
7. **代价一侧**：本方案不更快（约为手写 composite 的 2 倍），省集成代码也不独有
   （库宿主同价）。这些负结果界定了适用边界，不应隐藏。

## 9. 这套形式化的贡献边界

**可以声称**：

- 把"滞后一周期"量化为**相位裕度损失 `ω_c·L·Δt`** 与**闭环带宽上限 `B/(2πLΔt)`**
  （`doc/CONTROL_COST_OF_LAG.md`，有闭式验证 + 时间域确认）；
- 给出"单入口控制器模型下同周期双向数据流不可满足"的**充要条件**（定理 1 + 定理 3 的构造）；
- 给出单趟调度的**滞后下界**与构造（定理 2），并在内核与真实管理器上验证；
- 给出两趟方案的**充分性证明与 `O(|V|)` 存储**（定理 3）；
- 给出**配置期可判定**的拓扑校验规则（推论 2）。

**不能声称**：首次提出两阶段/层次化调度；首次用接口连接生成依赖；更快的实现。
两阶段本身在 FineMote、Orocos 等处已有；本文的贡献在于**把它作为单趟模型不可满足性的
必然结论来刻画**，并给出可判定性与代价分析。
