## 3. 实际实现范围

v1 增加：

- `controller_interface/include/controller_interface/hierarchical_controller_interface.hpp`：独立 mixin，只有 update_state/update_command 两阶段接口。
- `controller_manager/include/controller_manager/hierarchy.hpp`：name/parent 树记录、合法性校验、DFS 前序/后序计划、两阶段回调循环。
- `controller_manager/include/controller_manager/urdf_hierarchy.hpp`：从已解析 link/joint 记录建结构树，不是 XML parser。
- `controller_manager/include/controller_manager/controller_hierarchy_builder.hpp`：joint child link/anchor 祖先关系推导的实验算法，不是最终采用方案。
- `controller_manager/include/controller_manager/hierarchical_controller_executor.hpp`：独立执行器，尚未被 ControllerManager 调用。

## 4. v1 已知问题

1. state 返回错误后 executor 仍执行 command，没有阻止部分输出。
2. 计划与 controller 数组独立设置，长度/越界检查不能保证排列完整和实例匹配。
3. legacy update 在 state pass 执行，可能早于父目标计算，不保证同周期命令。
4. 缺少生命周期和频率检查；循环内仍 dynamic_cast。
5. anchor 推导多 joint 时可能依赖输入顺序，同 anchor 歧义未可靠处理。
6. 单根无环不证明控制语义正确，更不证明实时可调度。

不得把 v1 称为完整可用的树调度内核，不可直接用于硬件。

## 5. 必须纠正的早期结论

- vector 是存储结构，不能用来证明原生没有控制依赖；树/DAG 可以展开为线性计划。
- Humble 原生支持 branched chaining，多叉树本身不是新能力。
- 子控制器导出 reference，父控制器 claim 并写入；早期报告多次说反。
- 本地 Humble chainable API 有 reference export，没有新版本的 controller state export；不能照搬 Jazzy API 或只凭文档措辞判断。
- 父控制器可在 hardware.read 后直接读 joint state；获取新鲜原始反馈不一定需要叶到根遍历。
- 当父控制器依赖子控制器本轮计算的派生状态时，才有真正的双向阶段依赖问题。
- 原生已有链式激活/停用检查，不能宣称生命周期全是新增。
- 普通复合插件内部或拆分估计/命令组件也可实现双阶段，是必须比较的强基线。
- URDF 机械祖先关系不等于控制器依赖；URDF 不能推断 PID/MPC 等算法。

## 7. 当前研究契约与首版边界

每个节点 i 拆成 S_i（产生状态）和 C_i（产生命令）。父 p、子 c 的约束：

```text
S_c -> S_p
S_i -> C_i
C_p -> C_c
```

同步树采用后序 S、前序 C 是合法执行顺序。状态需有 sample timestamp、produced cycle、validity、fault source；reference 单写者。采样年龄与回调执行年龄要分开。

目标周期：硬件反馈快照 -> 后序状态计算 -> 前序命令计算到临时缓冲 -> 验证 -> 整组提交/故障动作 -> hardware.write。

临时缓冲不能提前别名到真实 command handle。软件整组提交不保证 CAN 或电机物理同步；跳过 write、置零或保持旧值都不是普适安全动作。写硬件时的故障仍需后端处理。

首版只做同频同步单树、显式配置、非活动状态才换拓扑；四舵轮底盘默认整车故障域。兄弟分支可能通过祖先耦合，先不承诺任意 isolate/fallback。生命周期转换不在 phase 回调随意进行；部分激活失败需回滚并报告回滚失败。

## 9. 下一步与停止标准

先做可证伪实验，再扩大 manager 改造：

1. 核验 Git/环境，以新提交保存阶段结果。
2. 实现最小可执行阶段依赖案例：子节点产生派生状态，父节点依赖本轮结果产生子目标；检查周期编号。纯算法实验不得称为 ROS/Gazebo 验证。
3. 相同算法实现普通 composite plugin/组件拆分对照，不能故意把 flat 顺序排错。
4. 注入 state/command 失败，比较混合周期输出、临时缓冲与故障动作。
5. 只有 manager 统一契约在检查、诊断、生命周期或接线成本上显示收益，才接主循环和父子接口。
6. 完整 colcon 测试、mock hardware、Gazebo 功能通过后，再讨论硬件实时性。

公平基线：原生 Humble chaining；估计/命令拆分（标明 Humble 所需额外接线）；普通复合插件；新 manager。

指标：输出一致性、源状态年龄、周期错配、部分命令提交、失败响应、动态分配、时间分布、deadline miss、增加模块的人工改动。实验最大耗时不是形式化 WCET；两次调用不一定更快。

停止门槛：若普通复合插件以相近成本满足相同保证，就停止大改 manager，转成复合控制器库。当前无实验结果，创新性仍待验证。
