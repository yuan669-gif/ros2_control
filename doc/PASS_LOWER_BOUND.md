# 最少几趟？——把定理 1 从"一趟不够"推广到"最少几趟"

日期：2026-09-22（2026-09-23 修正，见下方修正框）
关联：`doc/FORMAL_MODEL.md`（定理 1–3）、`doc/TWO_PASS_VS_SINGLE_PASS.md`（两趟实现）
测试：`hierarchical_control/test/test_pass_lower_bound.cpp`（4 用例，全部通过）
穷举脚本：`research/pass_lower_bound/search_min_passes.py`

> ## ⚠ 修正（2026-09-23，外部评审 R1）
>
> 本文早期版本在 §5.1 声称"`κ` 的计算是 NP-难的"。**该结论是错的，已撤回。**
>
> 反例即证明：对任意**无自环**有向图 `D`，任取一个顶点全序 `π`，把 `E_D` 分成
> "沿 `π` 增大的边"与"沿 `π` 减小的边"两类。前者不可能含回路（沿 `π` 严格递增），
> 后者也不可能（沿 `π` 严格递减）。于是
>
> ```text
> κ(D) = 0  若 E_D = ∅
> κ(D) = 1  若 E_D ≠ ∅ 且 D 无环
> κ(D) = 2  其余（只要 D 含任一有向环）
> ```
>
> 这是一个**完整分类**，不需要近似求解。（若允许自环 `u→u`，任意全序都无法满足它，
> 必须单独处理；物理模型中不存在自环。）
>
> **后果**：推论 P3 的"两趟最优"因此**不再是关于树形双向级联的实质结论**，
> 而是上述分类的一个平凡推论——任何含环的图两趟都够、且一趟不够。它只说明
> "完整阶段遍历的次数"不可能再降，**不能**推广成"最少 CPU 时间 / 最小端到端延迟 /
> 任意调度意义下的最优"。论文叙事必须相应弱化（见 §5.1）。
>
> 另外，评审指出该"边覆盖"模型本身是**阶段语义的近似**：一条边"曾在某一趟被满足"
> 不等于所有数值属于同一个逻辑周期/版本。实质结论应改由**实际阶段顶点**
> `S_i`（状态阶段第 `i` 趟）与 `C_i`（命令阶段第 `i` 趟）构成的依赖图来证明充分性，
> 而不是用合并后的要求图 `D`。这是尚未完成的工作。

## 0. 这补上了什么

`FORMAL_MODEL.md` 的定理 1 只说明**一趟不够**（双向对必有一条边陈旧），
定理 3 只说明**两趟充分**。两者之间有一个明显空洞：

> **最少需要几趟？两趟是不是最优的？**

本文回答这个问题，并给出一个**紧的**刻画。结论：

- 最少趟数 = **把要求图 `D` 的边划分成"无环子图"所需的最少类数**（充要，两方向都有证明）；
- 下界 = **两两冲突的最大边集大小**；在小图上穷举验证二者相等；
- **两趟执行对"每一级都双向的级联"是最优的，且与深度无关**——
  即实现里的两趟方案**不是"够用"，而是"最优"**。

这使 C3（两趟充分性）得到一个**平凡但有用**的伴随结论：在"完整阶段遍历次数"这一维度上，
两趟对任何含环的图都已经到底，因此**不存在**"再加几层调度就能消掉延迟"的方案；
定理 1 则是该刻画在"双向对"这一特例上的推论。
**不要把它读成"最优调度"**——见文首修正框与 §5.1。

## 1. 模型

沿用 `FORMAL_MODEL.md` 的单入口模型。定义**同周期要求图** `D = (V, E_D)`：

> 边 `u → v` 表示"`v` 必须观察到 `u` **本周期**写入的值"。

- 参考边 `(p,c) ∈ R`（父产参考、子消费）⇒ `p → c`；
- 状态边 `(c,p) ∈ S`（子产状态、父消费）⇒ `c → p`。

于是双向对给出 `p → c` 与 `c → p`，即 **2-环**；这正是定理 1 的场景。

一次**趟（pass）** = 节点集的一个全序。在这一趟里，边 `u → v` 被满足
**当且仅当 `u` 在 `v` 之前被访问**（单入口模型：每个节点每趟只有一个触点，
读写发生在同一处）。

一个 `k` 趟调度合法 **当且仅当** `D` 的每条边至少在其中一趟被满足。

---

## 2. 主要刻画

> **定理 P1（充要）.** `k` 趟调度存在 **当且仅当** `D` 的边集能划分成 `k` 个子集，
> 每个子集诱导的子图**无环**。

**证明.**

- **(⇐)** 设 `E_D = E_1 ⊔ … ⊔ E_k` 且每个 `E_i` 无环。取 `E_i` 的任一拓扑序 `π_i` 作为第 `i` 趟。
  该趟满足 `E_i` 的每条边（拓扑序保证 `u` 在 `v` 前）。于是每条边至少被满足一次，调度合法。
- **(⇒)** 设某 `k` 趟调度合法。第 `i` 趟满足的边集 `A_i` 必须与**一个全序**一致
  （该趟的访问顺序），故 `A_i` 无环。由 `∪ A_i = E_D` 得所需的划分。∎

记

```text
κ(D) = 覆盖 E_D 所需的最少无环类数        （即最少趟数）
```

> **推论 P1（一趟的充要条件）.** `κ(D) = 1` **当且仅当 `D` 本身无环；
> `κ(D) = 0` 当且仅当 `D` 无边。**

**证明.** `k = 1` 时划分就是 `D` 自身，由 P1 即得。∎

**这纠正了一个容易犯的错误**：不能把"最少趟数"等同于 `D` 的（凝聚图的）最长路长度。
一趟是**一个全序**，它可以同时满足**任意多个**彼此一致的边——
例如一条纯估计器链 `leaf → mid → root` 虽然最长路为 2，却**一趟即可**完成。

> **推论 P2（两趟对任意无环 `D` 都够）.** 若 `D` 无环，则 `κ(D) ≤ 1 ≤ 2`；
> 特别地，任何 `DAG` 都**不需要超过一趟**，因此更不需要超过两趟。

---

## 3. 下界与紧性

> **定理 P2（下界）.** 若边集 `S ⊆ E_D` **两两不能共处一趟**
> （即对任意 `e, f ∈ S`，子图 `{e, f}` 有环），
> 则 `κ(D) ≥ |S|`。

**证明.** 共处一趟的边集必须无环（P1 证明的 (⇒) 方向），故 `S` 中任意两条边必须分属不同类。∎

**紧性**：在**全部 n ≤ 3 的有向图**上穷举（共 `1 + 4 + 64 = 69` 个），
`κ(D)` 与下界处处满足 `κ(D) ≥ 下界`；而在本项目关心的一切情形上下界**取等**：

| 结构 | `D` | 无环？ | 下界 | `κ(D)`（穷举） |
|---|---|---|---|---|
| 单向估计器链 | `leaf→mid→root` | 是 | 1 | **1** |
| 单向参考链 | `root→mid→leaf` | 是 | 1 | **1** |
| **双向对（定理 1）** | `p→c`、`c→p` | 否（2-环） | **2** | **2** |
| **深度 2 双向级联** | 每级一个 2-环 | 否 | **2** | **2** |
| **深度 3 双向级联** | 每级一个 2-环 | 否 | **2** | **2** |

## 4. 对本课题的直接后果

### 4.1 两趟对含环的图都够，而且一趟不够

> **推论 P3.** 对**每一级都双向**的级联（任意深度 `D`）：`κ = 2`。

**证明.** 每一级给出一个 2-环，其两条边两两冲突，故由 P2 得 `κ ≥ 2`；
另一方面把边分成"全部状态边"与"全部参考边"两类，
二者各自无环（分别是树的两个定向），故由 P1 得 `κ ≤ 2`。合起来 `κ = 2`。∎

**⚠ 这个结论有多强？** 按文首修正框，**任何**含环的 `D` 都有 `κ = 2`，
所以 P3 并不是树形双向级联的独有性质：它说明的是
"**完整阶段遍历次数**这一维度上，两趟已经到底了"。
把它读成"我们找到了树形结构的最优调度"是过度解读。
它在工程上仍然有用——它排除了"再多加几层调度就能消掉延迟"这条路——
但仅此而已。

### 4.2 深度不增加趟数，只增加"单趟的滞后"

这是本项目最容易被误读的一点，现在可以精确表述：

| 量 | 随深度 `D` 的变化 | 来源 |
|---|---|---|
| **最少趟数** `κ` | **恒为 2**（与 `D` 无关） | 本文推论 P3 |
| **单趟滞后** `L` | **恰为 `D`**（线性增长） | `FORMAL_MODEL.md` 定理 2 |
| 两趟滞后 | 0 | 定理 3 |

也就是说：**"深"本身不要求更多趟**；它惩罚的是**坚持只用一趟**的方案。
这与 `CONTROL_COST_OF_LAG.md` 的代价定律互补——
后者量化"单趟的滞后值多少"，本文说明"为什么不干脆多加几层调度"——
**因为两趟已经到底了**。

### 4.3 与上游的对照

- 上游的**单向**场景（估计器链、参考链）要求图**无环**，故按推论 P1**一趟即可**，
  上游在那里的处理是正确的——这与"上游单向场景没问题"的实测一致；
- 上游的**双向**场景要求图含 2-环，`κ = 2`，**一趟模型无解**（定理 1），
  故只能静默降级——这与 `BIDIRECTIONAL_EDGE_ANALYSIS.md` 的实测一致。

**上游的状态/参考 chaining 各自覆盖单向场景**，这一说法现在有了精确的形式化含义：
它们分别对应"`D` 的某个无环子类"，而双向场景需要**两个**这样的类。

## 5. 限制（写进论文前必须正视）

1. ~~**`κ` 的计算是 NP-难的**（最少无环类覆盖）。~~ **已撤回（2026-09-23）**：
   `κ ∈ {0,1,2}` 有闭式分类（见文首修正框），一般 `D` 的 `κ` 平凡可判定，
   不存在近似求解问题。对本项目关心的**树形 + 双向**结构，闭式值 `κ = 2`（推论 P3）
   仍然成立，但它是上述分类的特例，**不是**关于树形结构的独立发现。
2. **模型仍是单入口、单频、同步**：与 `FORMAL_MODEL.md` 相同，不覆盖多频/异步/动态拓扑。
3. **"趟"的定义是最朴素的**：每个节点每趟一个触点。若允许"同一趟内对同一节点多次访问"
   （即更细粒度的读写分离），刻画会改变——这属于未来工作。
4. **穷举只到 3 个节点**（`1 + 2^2 + 2^6 = 69` 个有向图；4 节点是 `2^12 = 4096` 个，
   5 节点 `2^20`）。穷举验证的是分类而不是最优性，规模本身不是限制。
5. **"最优"一词的适用范围**：P3 只声称**完整阶段遍历次数**不可再降，
   **不**声称 CPU 时间、端到端延迟或一般调度最优。两趟的实际 CPU 开销见
   `HIERARCHY_FAIR_COMPARISON.md`（约为手写 composite 的 2 倍）。
6. **模型语义近似**：本模型只要求"每条边至少在某一趟顺序正确"，不保证所有数值属于
   同一逻辑周期。充分性的严格证明应建立在阶段顶点 `S_i`/`C_i` 的依赖图上，
   该证明尚未完成。
